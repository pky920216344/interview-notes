构造时把每个单词的出现下标存成递增列表；查询时两个列表各走一个指针，谁指的下标小谁前进。

思路

  • shortest 会被反复调用：预处理一次，把 单词 → 下标列表 存好，查询不再碰原数组。
  • 两张下标表都递增，双指针从小到大配对：|a[i] − b[j]| 更新答案后，较小下标一侧前进——换大的那侧只会更远。
  • 某一列表走完即可停：剩下的大下标不可能更近。

时间复杂度 构造 O(n)，单次查询 O(两表长度和)，空间复杂度 O(n)
1import java.util.*;2 3class WordDistance {4    // 预处理：单词 → 它出现的全部下标（天然递增），查询只在这两张表上走双指针5    private final Map<String, List<Integer>> pos = new HashMap<>();6 7    public WordDistance(String[] wordsDict) {8        for (int i = 0; i < wordsDict.length; i++)9            pos.computeIfAbsent(wordsDict[i], k -> new ArrayList<>()).add(i);10    }11 12    public int shortest(String word1, String word2) {13        List<Integer> a = pos.get(word1), b = pos.get(word2);14        int i = 0, j = 0, best = Integer.MAX_VALUE;15        // 谁指的下标小谁前进：较小一侧换下一个才可能更近，不会错过最优组合16        while (i < a.size() && j < b.size()) {17            int x = a.get(i), y = b.get(j);18            best = Math.min(best, Math.abs(x - y));19            if (x < y) i++; else j++;20        }21        return best;22    }23}
