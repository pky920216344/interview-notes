154. 寻找旋转排序数组中的最小值 II

  • 困难
  • 频度 20
  • 二分查找
  • 数组
  • 二分查找
  • 力扣已通过

二分拿 nums[mid] 和 nums[hi] 比：大于往右、小于往左；相等时 hi--，丢掉的重复值不影响最小值。

思路

  • [lo, hi] 里永远留着最小值；nums[mid] > nums[hi]：断点在右半，lo = mid + 1。
  • nums[mid] < nums[hi]：mid 到 hi 有序，mid 自己可能是答案，hi = mid。
  • nums[mid] == nums[hi]：无法判断断点在哪边，但 mid < hi 且 nums[mid] 就是 nums[hi] 的备份，hi-- 丢掉一个重复值不影响最小值——这是与 153 唯一的不同，也是最坏退化为 O(n) 的原因。

图解

最优解

时间复杂度 O(log n)（最坏 O(n)），空间复杂度 O(1)
1class Solution {2    public int findMin(int[] nums) {3        int lo = 0, hi = nums.length - 1;4        // [lo, hi] 里永远留着最小值；有重复时相等分支单独处理5        while (lo < hi) {6            int mid = lo + (hi - lo) / 2;7            if (nums[mid] > nums[hi]) {8                lo = mid + 1;   // 断点在右半，最小值在 (mid, hi]9            } else if (nums[mid] < nums[hi]) {10                hi = mid;       // mid 自己可能是最小值，区间收到 mid11            } else {12                hi--;           // 相等：nums[hi] 有备份（mid 处），丢掉不影响最小值13            }14        }15        return nums[lo];16    }17}
题目
已知一个长度为 n 的数组，预先按照升序排列，经由 1 到 n 次 旋转 后，得到输入数组。例如，原数组 nums = [0,1,4,4,5,6,7] 在变化后可能得到：
  • 若旋转 4 次，则可以得到 [4,5,6,7,0,1,4]
  • 若旋转 7 次，则可以得到 [0,1,4,4,5,6,7]

注意，数组 [a[0], a[1], a[2], ..., a[n-1]] 旋转一次 的结果为数组 [a[n-1], a[0], a[1], a[2], ..., a[n-2]] 。

给你一个可能存在 重复 元素值的数组 nums ，它原来是一个升序排列的数组，并按上述情形进行了多次旋转。请你找出并返回数组中的 最小元素 。

你必须尽可能减少整个过程的操作步骤。

示例 1：

输入：nums = [1,3,5]
输出：1

示例 2：

输入：nums = [2,2,2,0,1]
输出：0

提示：

  • n == nums.length
  • 1 <= n <= 5000
  • -5000 <= nums[i] <= 5000
  • nums 原来是一个升序排序的数组，并进行了 1 至 n 次旋转
