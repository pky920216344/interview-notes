线程池 + 「已见集合」并发的 BFS：worker 抓页面、同主机新链接继续入池；pending 计数归零时放闸收工。

思路

  • 本质还是 BFS，只是队列的任务由线程池并发执行；正确性全靠 ConcurrentHashMap.newKeySet() 的 seen.add 原子返回值：返回 true 才入队，天然去重。
  • 主机过滤：截取 :// 到下一个 / 之间为主机名，异主机链接直接丢弃。
  • 收工判断是并发 BFS 的难点：pending 计「已提交未完成」的任务数，先 incrementAndGet 再提交子任务；某个任务把计数减到 0 时 CountDownLatch 放闸——0 意味着没有任何在飞的任务。
  • 结果顺序并发下不定，判题按集合比对；本地用单线程 BFS 参考解对拍「可达集合一致 + 无重复」。
