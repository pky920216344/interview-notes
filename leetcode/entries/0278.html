278. 第一个错误的版本

  • 简单
  • 频度 2
  • 二分查找
  • 二分查找
  • 交互
  • 待提交

二分找第一个 true：坏版本往左压（hi = mid），好版本往右走（lo = mid + 1），相遇处即答案。

思路

  • 「第一个坏版本」有单调性：坏的后面全坏，正好套二分模板「找第一个满足条件的」。
  • mid 已坏 ⇒ 答案在 mid 或左边，hi = mid（不能 mid - 1，mid 本身可能就是答案）。
  • mid 还好 ⇒ 答案严格在右边，lo = mid + 1。
  • mid 用 lo + (hi - lo) / 2：n 可达 2^31 - 1，(lo + hi) / 2 会先溢出。

最优解

时间复杂度 O(log n)，空间复杂度 O(1)
1public class Solution extends VersionControl {2    public int firstBadVersion(int n) {3        // 二分找第一个坏版本：坏往左压，好往右走，lo 停下的地方就是答案4        int lo = 1, hi = n;5        while (lo < hi) {6            int mid = lo + (hi - lo) / 2;   // (lo + hi) / 2 在 n 接近 2^31 时会溢出7            if (isBadVersion(mid)) hi = mid;   // mid 已坏：第一个坏的在 mid 或它左边8            else lo = mid + 1;                 // mid 还好：答案严格在 mid 右边9        }10        return lo;11    }12}
题目

你是产品经理，目前正在带领一个团队开发新的产品。不幸的是，你的产品的最新版本没有通过质量检测。由于每个版本都是基于之前的版本开发的，所以错误的版本之后的所有版本都是错的。

假设你有 n 个版本 [1, 2, ..., n]，你想找出导致之后所有版本出错的第一个错误的版本。

你可以通过调用 bool isBadVersion(version) 接口来判断版本号 version 是否在单元测试中出错。实现一个函数来查找第一个错误的版本。你应该尽量减少对调用 API 的次数。

 

示例 1：

输入：n = 5, bad = 4
输出：4
解释：
调用 isBadVersion(3) -> false 
调用 isBadVersion(5) -> true 
调用 isBadVersion(4) -> true
所以，4 是第一个错误的版本。

示例 2：

输入：n = 1, bad = 1
输出：1

提示：

  • 1 <= bad <= n <= 231 - 1
