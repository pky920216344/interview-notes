197. 上升的温度

  • 简单
  • 频度 1
  • SQL
  • 数据库
  • 待提交

自连接按「日历差恰一天」配对，左表温度更高就留下它的 id。

思路

  • 「昨天」按日历日期差算：DATEDIFF(w1.recordDate, w2.recordDate) = 1——不是表里 id 相邻的两行（表可能缺日期）。
  • 配对后 w1.temperature > w2.temperature 即升温日，输出 w1.id。
  • MySQL 8 也可用窗口函数：LAG(temperature) OVER (ORDER BY recordDate) 与 LAG(recordDate) 双列校验，效果等价。
  • 返回无顺序要求，不用 ORDER BY。

最优解

时间复杂度 O(n²)（recordDate 建索引后近似 O(n)），空间复杂度 O(1)

题目

表： Weather

+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| recordDate    | date    |
| temperature   | int     |
+---------------+---------+
id 是该表具有唯一值的列。
没有具有相同 recordDate 的不同行。
该表包含特定日期的温度信息

编写解决方案，找出与之前（昨天的）日期相比温度更高的所有日期的 id 。

返回结果 无顺序要求 。

结果格式如下例子所示。

示例 1：

输入：
Weather 表：
+----+------------+-------------+
| id | recordDate | Temperature |
+----+------------+-------------+
| 1  | 2015-01-01 | 10          |
| 2  | 2015-01-02 | 25          |
| 3  | 2015-01-03 | 20          |
| 4  | 2015-01-04 | 30          |
+----+------------+-------------+
输出：
+----+
| id |
+----+
| 2  |
| 4  |
+----+
解释：
2015-01-02 的温度比前一天高（10 -> 25）
2015-01-04 的温度比前一天高（20 -> 30）
