995. K 连续位的最小翻转次数

  • 困难
  • 频度 1
  • 贪心
  • 前缀和/差分
  • 位运算
  • 队列
  • 数组
  • 前缀和
  • 滑动窗口
  • brute-force-search
  • 待提交

从左到右贪心：最左的实际 0 只能当某段翻转的起点；用「盖着的翻转奇偶 + 退出标记」免真翻。

思路

  • 最左边那个实际为 0 的位置 i，必须有一段翻转以它开头（更靠左的起点早已决策完），所以贪心唯一。
  • 不真翻数组：flip 记录「盖着 i 的翻转次数」的奇偶，实际值 = nums[i] ^ flip；为 0 就在 i 开新翻转。
  • diff[i+k] ^= 1 记退出点：扫到 i 时先 flip ^= diff[i]，到期的翻转自动作废。
  • 若实际 0 出现在 i + k > n 处，剩余不足 k 个翻不了，返回 -1。

图解

最优解

时间复杂度 O(n)，空间复杂度 O(n)
1class Solution {2    public int minKBitFlips(int[] nums, int k) {3        int n = nums.length, ans = 0, flip = 0;   // flip：盖着当前位置、还没退出的翻转次数奇偶4        int[] diff = new int[n + 1];   // 差分标记：翻转从 i 生效、到 i+k 作废5        for (int i = 0; i < n; i++) {6            flip ^= diff[i];   // 走到退位点，到期的翻转在这里扣除7            if ((nums[i] ^ flip) == 0) {   // 被 flip 次翻转后的实际值是 0：必须从这翻一段8                if (i + k > n) return -1;   // 剩余不足 k 个，没法整段翻9                ans++;10                flip ^= 1;11                diff[i + k] ^= 1;12            }13        }14        return ans;15    }16}
题目

给定一个二进制数组 nums 和一个整数 k 。

k位翻转 就是从 nums 中选择一个长度为 k 的 子数组 ，同时把子数组中的每一个 0 都改成 1 ，把子数组中的每一个 1 都改成 0 。

返回数组中不存在 0 所需的最小 k位翻转 次数。如果不可能，则返回 -1 。

子数组 是数组的 连续 部分。

示例 1：

输入：nums = [0,1,0], K = 1
输出：2
解释：先翻转 A[0]，然后翻转 A[2]。

示例 2：

输入：nums = [1,1,0], K = 2
输出：-1
解释：无论我们怎样翻转大小为 2 的子数组，我们都不能使数组变为 [1,1,1]。

示例 3：

输入：nums = [0,0,0,1,0,1,1,0], K = 3
输出：3
解释：
翻转 A[0],A[1],A[2]: A变成 [1,1,1,1,0,1,1,0]
翻转 A[4],A[5],A[6]: A变成 [1,1,1,1,1,0,0,0]
翻转 A[5],A[6],A[7]: A变成 [1,1,1,1,1,1,1,1]

提示：

  • 1 <= nums.length <= 105
  • 1 <= k <= nums.length
